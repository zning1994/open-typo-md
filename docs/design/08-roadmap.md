# 08 · 路线图

原则：**每个里程碑结束时，产物都是可用的**（可以真的拿来写东西），而不是「半个功能」。
排序依据是原则 P5：先把 CommonMark 做到零损耗，再铺功能面。

---

## M0 · 骨架（2–3 周）

搭好地基，让后面的人能并行干活。

- pnpm workspace + TS project references + Vite/tsup 构建
- Electron 三进程骨架、`HostBridge` 接口与 Electron/内存两套实现
- 最小编辑器：CodeMirror 6 + Markdown 语法高亮（**还没有实时预览**）
- 打开 / 保存 / 另存为；原子写入
- CI：lint、typecheck、单测、三平台构建

**验收**：能打开一个 `.md`，以纯源码模式编辑并保存，保存后文件逐字节一致。

---

## M1 · 实时预览内核（4–6 周）· 项目成败在这里

- 装饰引擎：`Decoration` 四类的规则框架（02 §2）
- 「光标进入即显源码」算法与激活范围规则（02 §3）
- CommonMark 全集的呈现规则：标题、强调、行内代码、链接、图片、列表、引用、
  代码块、分隔线
- 交互细节：`atomicRanges` 光标穿越、点击定位、行首缩进补偿（02 §4）
- **IME 正确性**：装饰冻结机制 + 中日韩 Playwright 用例
- 撤销 / 重做、查找 / 替换
- 源码模式切换
- 保真闭环测试 + CommonMark 规范符合性测试

**验收**：能用它舒服地写一篇纯 CommonMark 长文；输入延迟 p95 < 16ms；
IME 用例全绿；打开-保存字节一致。

> 这个里程碑如果做不好，后面做什么都没意义。建议在这里多花时间，
> 并在结束时做一次真实用户试用（找 5 个人各写一篇长文）。

---

## M2 · GFM 与结构化编辑（4–5 周）

- 表格：渲染 + 网格编辑器 widget + 写回 transaction（02 §6）
- 任务列表（可点击勾选）、删除线、自动链接、脚注
- 图片：粘贴 / 拖入 → 附件目录，相对路径解析（04 §5）
- 粘贴 HTML → Markdown；复制为富文本
- 输入行为：列表续行、Tab 缩进、自动配对、选中包裹（02 §7）
- 代码块：语言高亮、语言选择器

**验收**：能完成一篇带表格、图片、代码的技术文档，全程不用切源码模式。

---

## M3 · 工作区与内容扩展（4–5 周）

- 文件树侧边栏、多标签页、会话恢复
- 大纲面板、字数统计
- 文件监听、外部修改冲突处理、崩溃恢复（04 §3、§4）
- 命令面板、可配置快捷键
- 数学公式（KaTeX，行内 + 块级）
- Mermaid 图表（懒加载）
- YAML front matter

**验收**：可以把它当日常主力编辑器用一整周而不想切回去。

---

## M4 · 主题与导出（3–4 周）

- 主题引擎：变量与类名契约、热加载、5 套内置主题（05）
- 深色模式、跟随系统
- 导出 HTML（自包含单文件）
- 导出 PDF（打印管线、页眉页脚、分页控制）
- 打印样式
- 设置界面（含 JSON Schema 驱动的表单）

**验收**：社区能凭文档做出自己的主题；导出的 PDF 能直接交付。

---

## M5 · 插件系统（4–5 周）

- `@typo/plugin-api` v1.0 冻结
- 插件加载、生命周期、自动注销、热重载
- 权限清单与 main 侧代理校验（05 二、ADR-0004）
- 把内置的数学 / 图表 / 脚注**重构成插件**，验证 API 完备性
- Pandoc 检测与 DOCX / ePub / LaTeX 导出；DOCX 兜底路径
- 全文搜索（Level 1 无索引）
- 插件开发文档 + 模板仓库

**验收**：第三方能照文档写出一个语法扩展插件并正常工作。

---

## M6 · 打磨与 1.0（4–6 周）

- 专注模式、打字机模式
- 拼写检查（系统词典）
- 国际化（中 / 英）+ RTL
- 无障碍整改（axe 扫描清零主要违规）
- 全文搜索 Level 2（SQLite FTS）
- 自动更新、代码签名与公证、便携版
- 性能基准全部达标
- 用户文档站

**验收**：达到 00 号文档中 G1–G4 的全部指标，可以发 1.0。

---

## 1.0 之后的候选方向

按价值排序，不承诺时间：

1. **插件真隔离**：把插件挪进 utility 进程 / Worker + RPC，兑现 ADR-0004 的演进项。
2. **协同编辑**：Y.Text 直接套在缓冲区文本上（源码优先模型的红利），
   配合 y-webrtc / 自建服务。
3. **Web 版**：`apps/web` 补完 File System Access API 实现，内核零改动。
4. **版本历史**：本地快照 / Git 集成，文档级 diff 视图。
5. **移动端**：内核已是纯 Web，理论可行，但触屏交互要重新设计。

## 团队与节奏的说明

上面的周数按 **1–2 名全职工程师** 估算，且 M1 的不确定性最大（可能翻倍）。
如果是业余时间开发，建议：

- 把 M0 + M1 当作唯一目标先做出来，其余全部砍掉 —— 一个只支持 CommonMark
  但实时预览做得扎实的编辑器，已经比一堆功能齐全但手感别扭的项目更有价值；
- M2 之后再考虑对外招募贡献者，因为那时 API 边界与测试基线已经稳定，
  新人能安全地并行工作。
