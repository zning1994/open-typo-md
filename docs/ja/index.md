## カーソルが入ったときだけ、記法が現れる

これがこのエディタの中核であり、「左にソース・右にプレビュー」との決定的な違いです。
普段は組版された文字が見えていて、カーソルを入れるとその要素の Markdown 記法だけが
その場に現れ、編集できるようになります。**モードの切り替えも、2 つ目のペインもありません。**

## コードも数式も図も、同じ編集領域の中に

コードブロックは言語ごとにハイライトされ、本文と一緒に折り返されることはありません。
数式は KaTeX、` ```mermaid ` フェンスはそのまま図になります。すべて遅延読み込みなので、
これらを使わない文書が起動時にコストを払うことはありません。

## 現在の状態

**すでに使えます。1.0 に向けて開発中です。** バージョンは 0.2.0。直近の作業区切り
（マイルストーン「M4.5」）が完了したところです。

GFM（表・タスクリスト・打ち消し線・脚注）、数式、Mermaid 図、アウトラインパネル、
コマンドパレット、クラッシュ復旧、6 種類のテーマ、HTML / PDF 書き出し、リッチテキストとして
コピー、HTML を貼り付けて Markdown に変換、表の編集、ファイルツリー、タブ、セッション復元、
設定パネル、インライン HTML の描画、ショートカットのカスタマイズ、フォーカスモード、
タイプライターモード、3 言語の UI（中国語 / 英語 / 日本語）—— ここまでは動きます。

v0.2.0 では、ファイルツリーからの新規作成 / 名前変更 / ゴミ箱への移動、Quick Open（⌘P）、
ワークスペース全体の検索（⌘⇧F）、アウトラインの絞り込みと折りたたみ、更新の確認が
加わりました。

**次は AI です**。書き直し、翻訳、要約、文書への質問 —— どれも標準機能で、
何もインストールする必要はありません。そして **AI が文書を直接書き換えることはありません**：
変更は必ず目に見える差分として提示され、⌘Z 一回で元に戻せます。

**まだないもの**：AI（M5、まだ一行も書いていません）、ユーザーテーマディレクトリと
ホットリロード、ブロックレベル HTML の描画（これは**あえて実装しない**判断です。
理由はロードマップに）、表の列幅のドラッグ、PDF のヘッダー / フッターと目次のページ番号、
ファイルツリー内でのドラッグ移動、Pandoc 経由の書き出し（DOCX / ePub）。

**公開プラグイン機構も「あえて作らない」判断です**（v1）：サードパーティのコードは
読み込みません。将来公開するのは制御された Tool API です。

各マイルストーンの末尾には「計画と実際に何が違ったか」を必ず書いています。
何を削ったか、なぜ削ったかを一つずつ残したその一覧は、隠すべき恥ではなくプロジェクトの一部です。

## 試すには

タグ付きリリースはまだありませんが、`main` へのプッシュごとに 3 プラットフォーム分の
インストーラが
[Actions](https://github.com/zning1994/mosu/actions) に生成されます。

⚠️ **これらのビルドは署名されていません。** macOS は初回起動を拒否します（右クリック →
「開く」、または「システム設定 → プライバシーとセキュリティ」から許可）。Windows では
SmartScreen が警告します。アプリの問題ではなく、署名証明書をまだ用意していないだけです。

ソースから動かすほうが簡単です。

```bash
pnpm install
pnpm dev
```

## ドキュメントについて

**設計ドキュメントは中国語で書かれており、翻訳していません。** これは未完成なのではなく、
意図的な判断です。設計ドキュメントは 9 本と ADR 5 本あり、しかも開発の進行に合わせて
変わり続けます。動き続ける文書を翻訳するコストは「1 回の翻訳」ではなく「改訂のたびに
言語の数だけ翻訳」であり、それは払い続けられません。

とはいえ機械翻訳してでも読む価値はあります。機能の一覧ではなく、**取捨選択と失敗**の
記録だからです。

- [なぜ ProseMirror ではなく CodeMirror 6 か](/adr/0002-editor-core) ——
  リッチテキストエディタの文書モデルは本質的に中間表現を必要とし、それが
  「ソースこそが真実」と正面から衝突するため；
- [なぜ Markdown パーサーを 2 つ使うのか](/adr/0003-dual-parser) ——
  編集には逐次的で位置が正確な解析が、書き出しには完全な意味解析が要る。
  1 つで兼ねるとどちらも中途半端になる；
- [macOS で PDF が白紙になる不具合を CI 7 周かけて追った話](/design/06-export) ——
  6 つの結論を立てては自分で否定し、最後は変数を総当たりで測って 1 つのフォントに行き着いた；
- [HTML を解析せずに文書中の HTML を描画する方法](/design/02-editor-core) ——
  サニタイザを使う道自体を避けた。Electron の中でサニタイザに 1 つ穴があれば、
  XSS はそのまま RCE になるため。

## Typora との関係

同種の体験を提供する商用製品として [Typora](https://typora.io/) があります。本プロジェクトは
**独立した実装**であり、コード・素材・UI リソースを一切流用していません。借りているのは
「継ぎ目のないライブプレビュー」という操作のあり方だけです。両者に資本・組織上の関係は
ありません。
