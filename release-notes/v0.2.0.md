This release is about **working in a folder rather than a file**, and about two
layout bugs that a real long document exposed.

If you kept 0.1.0 open for a long piece of writing, you probably hit one of them.

## Fixed

- **Clicking put the cursor on the wrong line.** In a long document, clicking a
  visible line could insert text one or two lines below it, and the status bar
  agreed with the wrong line. It looked like a scrolling bug; it was not. Heading
  and code-block spacing was written as CSS `margin`, and margins do not count
  towards the line heights CodeMirror measures — so its height map drifted a
  little further with every heading above the click.
- **Wide tables pushed their right-hand columns off screen.** Table cells did not
  wrap, so a column was as wide as its longest cell, and scrolling sideways moved
  the whole editor instead of the table. Cells now wrap — including long URLs and
  unbroken identifiers — and the table stays inside the text column.

## The file tree is now a workspace

- Markdown files show their **first heading** as the label, with the file name
  kept as a subtitle. YAML front matter is skipped, and a `#` inside a fenced
  code block is not mistaken for a heading.
- Right-click to **create, rename, or move to the trash**, plus open in a new
  tab, copy path, and reveal in the file manager. Deleting goes to the system
  trash, never a straight `unlink`.
- **Filter and sort** by name or modified time.

Renaming a file that is open keeps your unsaved edits and simply follows the file
— it does not reload from disk, and the next save goes to the new name.

## Finding things

- **Quick Open** (`⌘P` / `Ctrl+P`) — jump to a document by file name, path, or
  heading. Open tabs come first. Previously `⌘⇧P` only searched *commands*, so
  typing a file name found nothing.
- **Find in Workspace** (`⌘⇧F` / `Ctrl+Shift+F`) — search every Markdown file in
  the folder, with file, line number and surrounding text. Results stream in as
  they are found. Supports case, whole word, regular expressions, and limiting to
  a subfolder. `⌘F` still searches the current document.

## The outline panel grew up

Filter by keyword (matching headings keep their parents, so you can see where a
result sits), collapse individual sections or everything or down to a level,
drag the left edge to resize, and optional section numbers. The current section
now scrolls into view instead of sitting off-list.

None of it touches the document or the cursor.

## Settings are findable now

On macOS, **Settings…** is in the Mosu menu, right under About, where it belongs.
It used to be under View only, which meant many people never found it — and the
**interface language** lives in Settings, so that was unreachable too.

## Check for Updates

There is now a menu item that checks whether a newer release exists — under the
Mosu menu on macOS, under Help elsewhere.

It is deliberately narrow, and worth stating plainly:

- It runs **only when you click it**. There is no check on launch and no
  background polling.
- It sends **one anonymous GET** and nothing else. No token, no machine
  identifier, and it does not report the version you are running — the comparison
  happens on your machine.
- You can **turn it off entirely** in Settings, and the block happens before any
  request leaves the process.

It tells you and opens the download page. It does not download or install
anything: real auto-update needs code signing on Windows first, and shipping an
update channel that skips signature verification would be worse than having none.

## Upgrading

0.1.0 has no update mechanism, so this is a manual download — the same files as
last time, with the same platform notes:

**macOS** — signed with a Developer ID certificate and notarised. Take the
`arm64` build on Apple Silicon, `x64` on Intel.

**Windows** — `Mosu-0.2.0-x64.exe`, or `-arm64.exe` on an Arm machine.
`Mosu-0.2.0-x64-portable.exe` runs without installing. These are **still not
signed**, so SmartScreen will warn; click "More info" → "Run anyway". The
reasoning is unchanged and is in the README.

**Linux** — `Mosu-0.2.0-x86_64.AppImage` (or `-arm64`), or the `.deb` / `.tar.gz`:

```bash
chmod +x Mosu-*.AppImage && ./Mosu-*.AppImage
```

Your settings and session carry over. The `.zip` files next to the macOS `.dmg`s
and the `latest*.yml` files are metadata for an auto-updater that still does not
exist; you do not need them.

## Not there yet

The plugin system, drag-to-resize table columns, dragging files within the tree,
cross-file replace, indexed search for very large workspaces, export preview,
PDF headers and footers, user theme directories, Pandoc-based export, and
auto-update.

As before, everything that differed from the plan is written down at the end of
each milestone in the roadmap rather than quietly dropped.
